# DPC-AIO 0.7.0 — Monolithic AIO + Show Hidden + Enterprise Policy Hub

## Status

Approved in chat on 2026-08-22. This spec records the approved design for implementation.

## Goal

Keep DPC-AIO as one monolithic APK that compiles all current modules, but separate **compiled/integrated** from **currently usable**. Add a persistent **Show hidden** mode, an additional **Developer / Lab** mode, a central management-capability model, an Enterprise Policy Hub for Android 16/17 enterprise APIs, and local diagnostics without bypassing Android ownership or permission enforcement.

## Non-goals

- Do not split the product into dynamic-feature APKs or plugins.
- Do not remove Shizuku, Dhizuku, Knox mock, NFC lab, scenario tooling, or other existing modules from the monolithic build.
- Do not use root, hidden/non-SDK APIs, signature spoofing, or permission bypasses to make an unavailable policy executable.
- Do not claim an unsupported policy is usable merely because its classes compile.
- Do not send telemetry or diagnostics off-device.
- Do not change the existing dual-QR provisioning contract except where tests show a regression.

## Architecture

### 1. Management context

Introduce a pure model in `:core-model` describing the runtime context used for capability decisions.

```kotlin
enum class OwnershipMode { NONE, PROFILE_OWNER, DEVICE_OWNER }

data class ManagementContext(
    val apiLevel: Int,
    val ownership: OwnershipMode,
    val organizationOwnedProfile: Boolean,
    val samsungDevice: Boolean,
    val knoxAvailable: Boolean,
    val knoxLicenseActive: Boolean,
    val buildTrack: BuildTrack,
    val showHidden: Boolean,
    val developerMode: Boolean,
)
```

The Android app creates this context from `Build.VERSION.SDK_INT`, `DevicePolicyManager`, manufacturer/runtime signals, existing Knox runtime state, and persisted UI preferences.

### 2. Capability requirements and status

Each user-facing module or policy has explicit requirements.

```kotlin
enum class CapabilityAvailability {
    AVAILABLE,
    OWNER_REQUIRED,
    PROFILE_OWNER_ONLY,
    DEVICE_OWNER_ONLY,
    ORG_OWNED_PROFILE_REQUIRED,
    API_UNAVAILABLE,
    SAMSUNG_ONLY,
    KNOX_LICENSE_REQUIRED,
    LAB_ONLY,
    EXPERIMENTAL,
    UNSUPPORTED,
    ERROR,
}

enum class VisibilityClass { NORMAL, HIDDEN, LAB, EXPERIMENTAL }
enum class OwnershipRequirement {
    ANY,
    DEVICE_OWNER,
    PROFILE_OWNER,
    DEVICE_OR_PROFILE_OWNER,
    DEVICE_OR_ORG_OWNED_PROFILE,
}
enum class RiskClass { LOW, MEDIUM, HIGH }
```

A pure `CapabilityResolver` evaluates requirements before any action. Android framework exceptions remain a final safety boundary, not the primary availability detector.

### 3. Persistent UI preferences

Store user-facing mode preferences in device-protected SharedPreferences:

- `showHidden` default `false`
- `developerMode` default `false`
- `selectedFilter` default `all`
- `showExperimental` default `false`

`developerMode` reveals LAB entries and permits their UI actions when all normal API/ownership/OEM requirements are satisfied; it does not grant permissions or ownership.

### 4. Module Center

Keep `DpcModuleRegistry` as the compile-time ownership registry for all monolithic modules, but enrich descriptors with:

- `minApi`
- optional `maxApi`
- ownership requirement
- visibility class
- risk class
- Samsung requirement
- Knox requirement
- optional feature key

The Module Center must show a resolved status such as `AVAILABLE`, `API_UNAVAILABLE`, `DEVICE_OWNER_ONLY`, `KNOX_LICENSE_REQUIRED`, or `LAB_ONLY` instead of only `Integrated`.

When **Show hidden** is off, hide entries that are explicitly HIDDEN/LAB/EXPERIMENTAL or impossible for the current platform/ownership when they are not useful to a normal operator. When on, show them with the exact reason actions are disabled.

Filters:

- All
- Available
- Unavailable
- Samsung / Knox
- Lab

### 5. Dashboard

The default dashboard exposes production-oriented surfaces:

- Enterprise Policy Hub
- Module Center
- Activity Explorer
- Permission Manager
- Samsung Settings
- Google Account Manager
- KnoxZT Framework
- Network / DNS / DoH
- Diagnostics

Scenario Recorder / Replay and NFC Lab move into an Advanced / Lab section that is rendered only when Developer / Lab mode is enabled. LAB actions remain subject to their normal API/ownership/runtime checks; modules remain compiled in the monolithic APK.

## Enterprise Policy Hub

Add `EnterprisePolicyHubActivity` to group capability-aware policy controls.

### Device policies

#### USB data signaling

- Framework API: `DevicePolicyManager.setUsbDataSignalingEnabled(boolean)` and `isUsbDataSignalingEnabled()`.
- API floor: 31.
- Before disabling, check `canUsbDataSignalingBeDisabled()`.
- Eligible owner: device owner or profile owner of an organization-owned managed profile.
- High risk. UI uses Preview → Apply → Result.
- Android 17 extends the practical impact of this policy to USB4/Thunderbolt PCIe tunneling; do not represent USB4/Thunderbolt as a separate undocumented policy.

#### Automatic time

- Framework API: `setAutoTimePolicy(int)` / `getAutoTimePolicy()`.
- API floor: 36.
- Eligible owner: device owner, profile owner for primary user, or organization-owned managed profile owner as documented by Android.
- Values: NOT_CONTROLLED, DISABLED, ENABLED.

#### Automatic timezone

- Framework API: `setAutoTimeZonePolicy(int)` / `getAutoTimeZonePolicy()`.
- API floor: 36.
- Same ownership model as auto time.

#### Thread network restriction

- Framework API: `DevicePolicyManager.addUserRestriction/clearUserRestriction` with `UserManager.DISALLOW_THREAD_NETWORK`.
- API floor: 36.
- Device owner or organization-owned managed profile owner acting device-wide.

#### NFC policy

Implement policy controls using documented user restrictions, not hidden settings:

- `UserManager.DISALLOW_NEAR_FIELD_COMMUNICATION_RADIO` — API 35, disables NFC radio by policy.
- `UserManager.DISALLOW_CHANGE_NEAR_FIELD_COMMUNICATION_RADIO` — API 36, prevents user changes to NFC radio state.

For organization-owned profile owner device-wide application, use the documented parent-profile DPM instance where required. Do not call undocumented NFC services.

### Applications

#### App Functions

- Framework API: `DevicePolicyManager.setAppFunctionsPolicy(int)` / `getAppFunctionsPolicy()`.
- API floor: 36.
- Values: NOT_CONTROLLED, DISABLED, DISABLED_CROSS_PROFILE.
- Owner: device owner/profile owner or caller with documented permission. DPC uses owner path only.
- Mark experimental in UI because Android 16 describes App Functions as beta/experimental preview.

#### Local network runtime permission

- API floor: 37.
- Permission: `android.permission.ACCESS_LOCAL_NETWORK`.
- Reuse the existing documented `setPermissionGrantState()` policy path.
- UI must target a selected package; it must not apply a global fabricated switch.

### Existing controls

The hub may link to existing package hide/suspend, runtime permission, private DNS, and network screens rather than duplicate those implementations.

## Policy gateway design

Extend `:policy-core` with explicit policy value types and interface methods for:

```kotlin
enum class TriStatePolicy { NOT_CONTROLLED, DISABLED, ENABLED }
enum class AppFunctionsPolicy { NOT_CONTROLLED, DISABLED, DISABLED_CROSS_PROFILE }
enum class DeviceRestriction { THREAD_NETWORK, NFC_RADIO, NFC_RADIO_CHANGES }

interface EnterpriseDevicePolicyGateway {
    fun getUsbDataSignalingEnabled(): PolicyResult<Boolean>
    fun setUsbDataSignalingEnabled(enabled: Boolean): PolicyResult<Unit>
    fun getAutoTimePolicy(): PolicyResult<TriStatePolicy>
    fun setAutoTimePolicy(policy: TriStatePolicy): PolicyResult<Unit>
    fun getAutoTimeZonePolicy(): PolicyResult<TriStatePolicy>
    fun setAutoTimeZonePolicy(policy: TriStatePolicy): PolicyResult<Unit>
    fun getAppFunctionsPolicy(): PolicyResult<AppFunctionsPolicy>
    fun setAppFunctionsPolicy(policy: AppFunctionsPolicy): PolicyResult<Unit>
    fun getDeviceRestriction(restriction: DeviceRestriction): PolicyResult<Boolean>
    fun setDeviceRestriction(restriction: DeviceRestriction, enabled: Boolean): PolicyResult<Unit>
}
```

`DevicePolicyGateway` extends this interface. `AndroidDevicePolicyGateway` performs SDK checks and returns `PolicyStatus.UNSUPPORTED` before calling APIs below their level.

Where a restriction is device-wide for an organization-owned managed profile, route the operation through `getParentProfileInstance(admin)` rather than applying it only inside the work profile.

## Diagnostics

Add a local `DpcDiagnosticsActivity` and pure `DpcDiagnosticsSnapshot`.

Display/export:

- Android API
- manufacturer/model
- DPC version
- Device Owner yes/no
- Profile Owner yes/no
- organization-owned managed profile yes/no
- Samsung detection
- Knox runtime availability/license state
- Shizuku/Dhizuku availability signal if obtainable without prompting
- module totals: integrated, visible, hidden, available, unavailable, lab

Export format: `dpc-diagnostics.json` through `ACTION_CREATE_DOCUMENT`.

Explicitly exclude:

- provisioning enrollment tokens
- Knox keys/tokens
- private keys
- account identifiers
- credentials
- foreign app SharedPreferences/databases
- raw logs from other apps

## Local event log

If an event log is added, it is local/device-protected only and records:

```text
timestamp
module
operation
capabilityStatus
result
exceptionClass
```

No remote endpoint and no background upload.

## Release and versioning

- DPC version: `0.7.0`
- Increment versionCode from 14 to 15.
- Preserve one monolithic APK with all current modules.
- Preserve the dual provisioning artifacts (`work-profile` and `device-owner`) and existing validators.
- Do not claim Android assemble success when Gradle is blocked by environment/network.

## Official API evidence checked during design

- Android 16 enterprise changes: Thread restriction, NFC management, App Functions, auto time/timezone.
- Android 17 enterprise changes: USB data policy effect extends to USB4/Thunderbolt; App Functions/device-state controls; local network access changes.
- DevicePolicyManager current reference: USB signaling APIs are API 31; auto time/timezone policy APIs and App Functions policy APIs are API 36.
