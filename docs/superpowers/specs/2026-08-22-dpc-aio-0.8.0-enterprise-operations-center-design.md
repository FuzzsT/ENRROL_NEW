# DPC-AIO 0.8.0 Enterprise Operations Center — Design

Date: 2026-08-22
Status: approved
Base: DPC-AIO 0.7.0 Enterprise Policy Hub
Reference input: `2.zip` static APK inventory and `DPC-AIO-2ZIP-IMPROVEMENT-ANALYSIS.md`.

## Goal

Extend the existing monolithic DPC-AIO APK with an Enterprise Operations Center while preserving the 0.7.0 `Show hidden` / `Developer-Lab` capability model, dual QR provisioning, and strict ownership/API gating.

## Source boundaries

The APK set in `2.zip` is reference material only. DPC-AIO may reproduce behavior that is available through documented Android Enterprise or Samsung Knox public APIs, but it must not copy private KLMS Agent, KnoxGuard, HDM, signature-only service contracts, private endpoints, hidden/non-SDK APIs, or proprietary implementation code discovered in DEX.

## Cross-cutting architecture

All mutating operations follow:

`Capability -> Preview -> Apply -> Readback -> VERIFIED/FAILED`

The core model remains independent of Android framework classes. Android-specific mapping lives in `policy-android`. Unsupported APIs return typed `PolicyResult` failures, not reflection/non-SDK fallbacks.

`Show hidden` may reveal unavailable capabilities and reasons; it never makes unavailable operations executable. `Developer/Lab` continues to gate lab tooling.

## 1. Compliance & Logs

### Security logging

Expose enable/disable state, callback readiness, retrieval and pre-reboot retrieval when supported. Device Owner retrieval must surface affiliation constraints rather than trying to bypass them. Log batches are normalized into app-owned records and kept in a bounded local rolling store. Manual export is JSONL/JSON with redaction enabled by default.

### Network logging

Expose enable/disable state, `onNetworkLogsAvailable` batch token handling, retrieval by real token and profile/device scope. Delegated network logging is represented as a capability requirement, not emulated.

### Logging states

Add capability/operation states for affiliation required, delegation required, logging disabled, waiting for callback, expired/missing batch and rate-limited retrieval.

## 2. System Update Policy

Support Android public `SystemUpdatePolicy` modes:
- system default / no policy;
- automatic;
- windowed with start/end minutes;
- postpone.

Support freeze periods on API 28+. Validate individual duration <= 90 days, no overlap/duplicates, and >= 60 days between adjacent periods before apply; framework validation remains authoritative. UI always previews requested vs current policy and reads back with `getSystemUpdatePolicy()` after apply.

## 3. Certificate & Credential Center

### CA certificates

Support public DPM install/list/check/remove CA certificate APIs. Imported certificates are PEM/DER selected by the user. The UI calls them `INSTALLED_USER_CA`, not globally trusted certificates.

### Key pairs

Support public DPM key-pair installation/removal and metadata/readback. Where stable SDK support exists, expose DPM key generation without private-key export. The application never exposes a "dump/export private key" feature.

### Delegation and grants

Use `DELEGATION_CERT_INSTALL` / `DELEGATION_CERT_SELECTION`, existing delegation infrastructure, `grantKeyPairToApp` and `getKeyPairGrants` when available. Shared-UID grants are surfaced as a warning.

Preview/future API (`API 10000`) remains visible only as unavailable under `Show hidden`; it is not compiled as a production operation.

## 4. Device Lifecycle Center

### Kiosk / Lock Task

Manage lock-task allowlist and public lock-task features. High-impact changes require confirmation and readback. No hidden escape/bypass mechanism is added.

### Device Security

Support password complexity, maximum failed password attempts for wipe, keyguard disabled features, camera and screen-capture policies. Wipe-threshold configuration is CRITICAL and requires explicit confirmation; no automated wipe testing.

### Application Control

Unify existing hide/suspend with uninstall block, application restrictions, clear app data and user-control-disabled packages where API/ownership permits. Clear-data is HIGH IMPACT and must name the target package before confirmation.

### Factory Reset Protection

Support public `FactoryResetProtectionPolicy` on API 30+ only for Device Owner or organization-owned Profile Owner. Account identifiers are supplied explicitly by the administrator; DPC-AIO does not infer email addresses or current accounts. Readback verifies the applied policy. Unsupported devices remain visible but disabled under `Show hidden`.

## 5. Work Profile / COPE

Support cross-profile packages, Android 14+ package-policy based contacts/caller-ID control where stable SDK allows, managed-profile maximum time off (non-zero minimum 72h), and personal-app suspension for organization-owned managed profiles.

DPC-AIO must handle `ACTION_CHECK_POLICY_COMPLIANCE` for maximum-time-off use. Cross-profile allowlisting does not claim to grant automatic cross-profile communication permission.

## 6. Organization & Affiliation

Organization ID/name and affiliation IDs are separate settings. Affiliation IDs are stable administrator-controlled values and are never randomized at each boot. Changes use preview/apply/readback. Affiliation state feeds Security Logging capability resolution.

## 7. Samsung Knox KPE

DPC-AIO extends the existing Knox license state machine instead of reimplementing KLMS Agent. Public KPE activation uses the public Knox SDK adapter when present. Keys are never hardcoded, exported in diagnostics, or included in release ZIPs.

Public adapters may expose ApplicationPolicy, CertificatePolicy, Kiosk, Firewall/VPN and Enhanced Attestation only when supported and licensed. Knox AuditLog remains visible only under `Show hidden` as `DEPRECATED_PLATFORM_API` for modern Android and is not an active 0.8.0 operation.

## 8. Diagnostics and local data

Diagnostics add logging state, pending network token/security batch state, system update policy, freeze-period count, certificate/key-pair counts, work-profile/affiliation summaries and Knox public capability states. Diagnostics/export never include private keys, KPE license secrets, enrollment tokens or credentials.

Local logging storage is bounded and device-private. Export is manual.

## 9. Release requirements

Version: `0.8.0`, versionCode `16`.

Release gate must include:
- existing 0.7.0 core/model tests;
- new operations-core tests;
- Android contract scans for public API use and callbacks;
- capability/status tests;
- dual QR validation;
- secret/private-key scan;
- non-SDK bypass scan;
- project/layout verifier;
- workflow YAML validation;
- plugin validation;
- final ZIP fresh-extract retest.

A Gradle assemble is reported PASS only if it actually exits zero. Network failure while fetching the Gradle distribution remains an environment blocker, never a build PASS.
