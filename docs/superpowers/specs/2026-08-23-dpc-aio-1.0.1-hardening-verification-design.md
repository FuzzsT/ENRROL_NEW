# DPC-AIO 1.0.1 Hardening & Verification — Design

## Status
Approved by user on 2026-08-23 after three section reviews.

## Goal
Harden DPC-AIO 1.0.0 by adding an exact-version build resolver, a host-side signed offline-bundle builder/inspector, and a device test harness that produces explicit source/build/install/owner/offline/permission/component verification states.

## Project-wide constraints
- Keep one monolithic DPC APK; host tools are support tooling, not a second management product.
- Never silently substitute a different Gradle version than the wrapper requests.
- Offline build readiness must distinguish missing JDK, SDK, build-tools, Gradle distribution, and cached dependencies.
- Private Ed25519 signing keys never enter the DPC APK, offline bundle, release ZIP, logs, or diagnostics.
- Offline bundle validation derives APK metadata from inspected APKs when platform tooling is available and never trusts filenames as package identity.
- Device tests default to SAFE mode and never factory-reset, wipe, remove Device Owner, delete accounts, or disable protected DPC/system components.
- Test outcomes are PASS, FAIL, SKIP, BLOCKED, or NOT_RUN; SKIP/BLOCKED never becomes PASS.
- Verification state is layered: SOURCE_VERIFIED, APK_BUILD_VERIFIED, APK_INSTALLED_VERIFIED, DEVICE_OWNER_VERIFIED, WORK_PROFILE_VERIFIED, FULL_OFFLINE_VERIFIED, PERMISSIONS_VERIFIED, COMPONENTS_VERIFIED.
- Existing 1.0.0 capability routing, offline no-network guarantee, Permission Manager 2.0, and Component Manager 2.0 behavior remain intact.

## 1. Build Resolver

Create a host tool under `tools/verify_aio/` that parses the wrapper distribution URL, resolves the exact required Gradle version, inspects Java and Android SDK availability, and reports readiness before build.

Resolution order:
1. existing wrapper cache / exact cached Gradle distribution;
2. exact local Gradle installation;
3. exact user-supplied Gradle distribution ZIP;
4. normal wrapper download only when online execution is allowed.

The resolver never changes `gradle-wrapper.properties` and never substitutes another Gradle version. User-supplied ZIPs are SHA-256 inspected and their extracted `gradle --version` must equal the wrapper requirement.

Offline readiness reports explicit codes including `GRADLE_VERSION_MISMATCH`, `JAVA_VERSION_MISMATCH`, `ANDROID_SDK_READY`, `ANDROID_PLATFORM_MISSING`, `BUILD_TOOLS_MISSING`, `DEPENDENCIES_MISSING`, `BUILD_OFFLINE_READY`, and `BUILD_ONLINE_REQUIRED`.

`verify-aio build --offline` performs readiness first, then invokes the exact resolved Gradle with `--offline :app-dpc:assembleEnterpriseDebug`, verifies the expected APK exists, and records build metadata. Failure to resolve tooling is BLOCKED, not FAIL of application source.

## 2. Offline Bundle Builder / Signer

Create `tools/offline_bundle/` with a Python CLI supporting:
- `create`
- `add-apk`
- `validate`
- `sign`
- `verify`
- `inspect`
- `preview`

Canonical bundle content is a directory or ZIP containing `manifest.json`, detached `manifest.sig`, policy files, APK/base/split files, and metadata index.

The builder computes SHA-256 for every package file. When `aapt2`, `apkanalyzer`, or equivalent local Android tooling is available, it records package name, version code/name, min/target SDK, split name, ABI hints, and certificate SHA-256. If a field cannot be inspected, the tool marks it unavailable instead of guessing from the filename.

Validation detects missing base APKs, duplicate splits, package-name mismatch, version mismatch, certificate mismatch, missing required split, and changed hashes.

Signing uses Ed25519 detached signatures over canonical manifest bytes. The signer accepts a private key only as an external file input, performs a pre-package secret scan, and never copies the key into output. Verification selects a public key by `keyId` from a trust-store file and returns `UNKNOWN_SIGNING_KEY` when absent.

`preview --api <n> --mode <mode>` performs host compatibility checks only and labels device-only capability decisions as requiring device verification.

## 3. Device Test Harness

Create `tools/verify_aio/device.py` and CLI subcommands that use ADB when available. No device/emulator is required for source verification; missing ADB/device produces BLOCKED/NOT_RUN results.

`device-preflight` records ADB connectivity, API, DPC version, users/profiles, current Device/Profile Owner, package-installer availability, optional Shizuku presence, storage, and offline-bundle readiness.

Provide safe functional test commands for:
- Device Owner/readback verification;
- Work Profile/Profile Owner readback verification;
- Permission Manager Grant/Deny/Default/readback/restore against a dedicated test target package;
- Component Manager Enable/Disable/Default/readback and reboot persistence against dedicated test components;
- local PackageInstaller base/split/tamper/missing-split behavior;
- FULL_OFFLINE smoke flow with network calls expected to remain zero;
- reboot recovery/readback where explicitly requested.

The harness never provisions or resets a personal device automatically. Commands that require a clean provisioning state report prerequisites and BLOCKED unless the user has prepared a test device.

Add a small `apps/aio-test-target` module containing reversible activities/alias/receiver/service and requested permissions used only by the harness.

## 4. Verification Reports and Release Gate

Create `verification-report.json` and optional Markdown output. Every test result includes test ID, expected, observed, status, timestamp, device/API when applicable, and no secrets.

Add `RELEASE-VERIFICATION.json` to release packaging. Its booleans/status fields are driven by evidence, not by inferred source correctness.

Extend host/pre-push gates to cover:
- build resolver contracts;
- offline bundle create/validate/sign/verify/tamper/unknown-key behavior;
- test-harness SAFE-mode guards and report schema;
- version 1.0.1 / versionCode 19;
- companion plugin 0.1.8;
- release packaging excludes private keys and transient build/cache directories.

The final release report must keep `apkBuildVerified=false` if the current environment remains unable to obtain the exact Gradle distribution or dependencies, even when source tests pass.
