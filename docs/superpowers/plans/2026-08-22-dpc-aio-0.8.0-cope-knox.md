# DPC-AIO 0.8.0 COPE and Knox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Work Profile/COPE, organization/affiliation controls and a bounded public-Knox capability surface without private/system protocol reproduction.

**Architecture:** Public DPM COPE operations extend the policy gateway. Knox work extends the existing license/startup core state machine and uses capability descriptors; no KLMS/KnoxGuard/HDM private protocol adapters are introduced.

**Tech Stack:** Kotlin/JVM 21, DevicePolicyManager, existing Knox core modules, optional runtime reflection only for detecting class presence (not invoking hidden Android APIs).

**Spec:** `docs/superpowers/specs/2026-08-22-dpc-aio-0.8.0-enterprise-operations-center-design.md`

## Global Constraints
- Maximum-time-off non-zero values must be >=72h.
- Affiliation IDs are explicit and stable.
- Knox AuditLog is deprecated/disabled on modern Android.
- No hardcoded KPE keys or secret export.
