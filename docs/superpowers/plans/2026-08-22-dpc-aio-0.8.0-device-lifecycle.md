# DPC-AIO 0.8.0 Device Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add lock-task/kiosk, device security, extended app controls and FRP with explicit high-risk confirmation and readback.

**Architecture:** Core policy specs describe requested state and risk; `policy-android` maps to public DPM methods. UI never issues wipe/reset operations; it only configures supported policy values.

**Tech Stack:** Kotlin/JVM 21, DevicePolicyManager, FactoryResetProtectionPolicy.

**Spec:** `docs/superpowers/specs/2026-08-22-dpc-aio-0.8.0-enterprise-operations-center-design.md`

## Global Constraints
- No automated wipe or factory-reset trigger.
- FRP account IDs are administrator-supplied strings; never inferred from device accounts.
- High/critical operations use Preview -> Confirm -> Apply -> Readback.
