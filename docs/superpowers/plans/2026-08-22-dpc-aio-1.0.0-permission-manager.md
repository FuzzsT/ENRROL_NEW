# DPC-AIO 1.0.0 Permission Manager 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the existing permission catalog into a per-app permission administration surface with actual/DPC/AppOps state separation, deterministic routing, batch preview/readback, and global permission policy.

**Architecture:** Extend permission core with inventory/capability/batch records; extend Android adapter for DPM readback and AppOps; keep Shizuku optional. UI operates on selected package and target user, never on a global implicit user.

**Tech Stack:** Kotlin core, DevicePolicyManager, PackageManager, AppOpsManager, Shizuku adapter, Android UI.

**Spec:** `docs/superpowers/specs/2026-08-22-dpc-aio-1.0.0-offline-application-control-design.md`

## Global Constraints
- Actual grant, DPC grant state, and AppOps are separate fields.
- Routes are capability-resolved before execution.
- Sensor/restricted grant limits disable unsupported actions.
- Batch restore is limited to prior DPC-managed states.
