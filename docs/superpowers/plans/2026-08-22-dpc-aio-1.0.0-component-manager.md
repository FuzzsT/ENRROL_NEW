# DPC-AIO 1.0.0 Activity / Component Manager 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add enable/disable/restore-default component-state control with multi-user routing, protected DPC components, batch snapshots, and readback.

**Architecture:** Extend activity core with component-state/risk/route models. Android adapter handles same-UID PackageManager state changes; Shizuku adapter handles authorized foreign-component shell commands. UI shows manifest, override, effective state and target user separately.

**Tech Stack:** Kotlin core, PackageManager, API 33 `setComponentEnabledSettings`, Shizuku `pm enable|disable|default-state --user`, Android UI.

**Spec:** `docs/superpowers/specs/2026-08-22-dpc-aio-1.0.0-offline-application-control-design.md`

## Global Constraints
- No fake DevicePolicyManager route for arbitrary foreign components.
- Critical DPC components cannot be disabled by normal UI/batch.
- DEFAULT means restore manifest behavior.
- Non-atomic batches are labeled as non-atomic.
