# DPC-AIO 0.6 Lab Network and Replay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build the 0.6.0 checkpoint with a local Knox lab bridge, verified network policy primitives, scenario record/replay, safe NFC lab replay, and native trace support.

**Architecture:** Pure Kotlin modules own policy/state/validation; Android modules adapt those interfaces to DevicePolicyManager, Binder/AIDL, VpnService, Account/Package/Activity APIs, and HostApduService. Instrumentation, mock, Binder, Hidden API, native, and lab/research adapters may be present in any build graph; the project gate must not denylist technologies. Every mutating operation still reports its actual runtime result and uses read-back where available.

**Tech Stack:** Kotlin/JVM, Android API 29–37, AIDL/Binder, DevicePolicyManager, VpnService, HttpsURLConnection DoH diagnostic client, NFC HostApduService/Ndef/IsoDep, JNI/C++17, Python contract gates.

**Spec:** `docs/superpowers/specs/2026-08-18-lab-network-replay-design.md`

## Global Constraints
- minSdk 29, compileSdk 37, targetSdk 37.
- ABIs: arm64-v8a, armeabi-v7a, x86_64, x86; page size runtime detected.
- Critical invariant: `release_gate.py` and verification scripts contain no technology denylist and never block a build because Frida, Xposed/LSPosed, Hidden API adapters, Binder helpers, Shizuku/Dhizuku, native instrumentation, or lab-tools are present.
- NFC replay accepts only `SYNTHETIC_TEST` or `OWNED_TEST` traces with `credentialBearing=false`.
- Capability availability is determined at runtime by the platform/result status rather than by source-folder or build-track policy gates.
