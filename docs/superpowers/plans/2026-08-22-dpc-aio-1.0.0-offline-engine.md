# DPC-AIO 1.0.0 Full Offline Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a no-network full-offline deployment engine with signed offline bundles, package-vault planning, recovery state, and offline-to-sync receipts.

**Architecture:** Add focused offline core/android modules. Core owns immutable bundle/readiness/stage/planning models and can be host-tested without Android. Android owns SAF import, signature/hash verification adapters, PackageInstaller sessions, device-protected persistence, and the UI coordinator.

**Tech Stack:** Kotlin/JVM core, Android Kotlin, PackageInstaller, Storage Access Framework, SHA-256/Ed25519, Python contract tests.

**Spec:** `docs/superpowers/specs/2026-08-22-dpc-aio-1.0.0-offline-application-control-design.md`

## Global Constraints
- FULL_OFFLINE performs zero backend/DNS/HTTPS calls.
- No private signing key in release tree.
- Preview -> Apply -> Readback for state changes.
- No unsupported operation is forced.
- Existing 0.9 enrollment flows remain compatible.
