# DPC-AIO 1.0.1 Device Test Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce safe ADB-backed evidence for install/owner/full-offline/permissions/components without destructive automatic provisioning.

**Architecture:** Host Python code separates ADB transport, preflight, safe test planning, and report generation. Missing device prerequisites result in BLOCKED/NOT_RUN, never inferred PASS.

**Tech Stack:** Python 3, adb subprocess, JSON/Markdown reports, Android test-target APK module.

**Spec:** `docs/superpowers/specs/2026-08-23-dpc-aio-1.0.1-hardening-verification-design.md`

## Global Constraints
- Default mode SAFE.
- Never factory-reset, wipe, remove owner/accounts, or disable protected components automatically.
- Functional mutation targets only the dedicated test package/components.

---

### Task 1: Device preflight and result model
**Files:** Create `tools/verify_aio/device.py`, `tools/verify_aio/report.py`; Test `tools/tests/test_101_device_harness.py`.
**Interfaces:** Produces `DeviceTestResult`, `DevicePreflight`, `run_device_preflight(adb)`.
- [ ] Write failing tests with fake command runner for no-device BLOCKED, connected API/user/owner parsing, and secret-free report serialization.
- [ ] Run; expect FAIL.
- [ ] Implement ADB runner abstraction, parsers, statuses, report model.
- [ ] Re-run; expect PASS.
