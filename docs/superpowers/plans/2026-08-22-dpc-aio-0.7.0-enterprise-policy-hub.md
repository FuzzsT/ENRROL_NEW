# DPC-AIO 0.7.0 Enterprise Policy Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade DPC-AIO to 0.7.0 while keeping one monolithic APK, adding capability-aware Show Hidden / Developer Lab visibility, an Android 16/17 Enterprise Policy Hub, and local diagnostics without bypassing Android ownership or permissions.

**Architecture:** Add a pure capability model and resolver in `:core-model`, construct runtime management context in the app, enrich the compile-time module registry with requirements, and route documented DPM operations through an expanded `DevicePolicyGateway`. UI remains Activity/Views-based to match the repository. Lab and experimental modules stay compiled but are hidden by default.

**Tech Stack:** Kotlin 2.4.10, Android SDK compile/target 37, Java 21, Android `DevicePolicyManager`, `UserManager`, device-protected SharedPreferences, repository Python contract tests, Gradle/AGP 9.3.1 when available.

**Spec:** `docs/superpowers/specs/2026-08-22-dpc-aio-0.7.0-enterprise-policy-hub-design.md`

## Global Constraints

- Keep one monolithic APK; do not flavor-split current modules out of `:app-dpc`.
- `showHidden=false`, `developerMode=false`, `showExperimental=false` by default.
- Never make an unavailable function executable by bypassing Android ownership, permissions, SDK guards, or non-SDK APIs.
- Use documented Android APIs only.
- USB data policy API floor is 31; auto-time/timezone and App Functions policy floor is 36; local-network runtime permission surface is API 37.
- Preserve existing work-profile and device-owner QR generation and validation.
- Diagnostics are local only and must exclude credentials, tokens, private keys, accounts, and foreign-app data.
- Version becomes `0.7.0`, versionCode `15`.
