# DPC-AIO 0.8.0 Logs and Updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add typed Security/Network Logging and System Update Policy operations with capability gating, local bounded storage and readback verification.

**Architecture:** Pure Kotlin policy models and validators live in `policy-core`; Android DPM calls and callback extraction live in `policy-android`/app receiver. UI is a focused Operations Center activity using the existing `CapabilityResolver` and `PolicyResult` conventions.

**Tech Stack:** Kotlin/JVM 21, Android DevicePolicyManager, org.json, existing hand-run Kotlin tests and Python contract tests.

**Spec:** `docs/superpowers/specs/2026-08-22-dpc-aio-0.8.0-enterprise-operations-center-design.md`

## Global Constraints

- Version remains 0.7.0 until the final release task.
- Public Android APIs only; no reflection/non-SDK enforcement bypass.
- `Show hidden` changes visibility, never authorization.
- Every mutating operation is preview/apply/readback.
- Log export is manual and redacted by default.
